# DSH 会话管理 1.2.0

本地插件 `@local/dsh-session-manager`，适配已核查的 DSH `0.2.2-rc.1`。无新增依赖，无安装脚本。所有会话停止和删除均需浏览器用户确认。

## 使用

更新已有插件后，请重启 DSH 并重新打开界面，确保 Host 和 Client 均加载 1.2.0。仅刷新页面不能清除 Host 的旧 JavaScript 模块缓存。重启前请自行结束或保存其他正在进行的工作，插件不会自动重启 DSH。

1. 点击左侧栏的会话管理入口，按标题、会话 ID 或工作目录搜索，筛选全部、已关闭、使用中、已归档会话。
2. 点击单个会话的删除按钮，或跨页选择最多 100 个会话后批量删除。受支持的使用中会话显示停止并删除入口。
3. 如目标仍在使用或有所属活动，勾选删除前停止使用中会话及其所属活动。此选项本身只重新生成预览，不执行停止。
4. 如需删除下级会话，勾选同时包含下级子会话，核对扩展后的名单。存在未选中的下级会话时拒绝删除父会话。
5. 核对会话 ID、文件数、日志大小、活动清单和保护项。使用中日志的大小为预览估值。
6. 输入预览给出的完整确认文本。需要停止时为 `STOP AND DELETE 数量`，其他情况为 `DELETE 数量`，随后点击最终确认按钮。
7. 等待停止活动、释放会话、等待缓存写回、取得写锁和文件删除各阶段的结果。操作中不能重复提交。

删除当前对话会中断该对话正在进行的工作。最终操作由独立 Host 插件管理，不依赖被删对话继续运行。

## 停止行为与失败结果

确认后请求取消所选会话的回合、停止所属后台任务和终端、停止并释放选中的下级 Agent，暂停相关定时任务，并等待所选 Agent 空闲及其完整生命周期释放。停止时会归档所选会话。

停止过程不自动回滚。停止失败、超时、仍有活动或停止后的写锁冲突时保留全部日志，报告已停止但未删除或未执行的目标。保留的会话可能已经归档，定时任务可能已经暂停，需要用户自行恢复。30 秒超时后，原停止过程可能仍在收尾，但不会在后台继续删除；再次删除必须重新预览和确认。

缓存和工作区清理在日志删除之前执行，清理失败时保留该目标的日志，重新预览后可重试。清理过程可能已移除部分缓存或工作区标记，不自动回滚。文件删除途中失败时立即停止余下批次，区分已删除、部分删除、失败和未执行，保留部分删除目标的选择项。当前有效日志最后删除，以保留失败后重新发现目标的机会。

日志删除完成后若索引对账失败，结果仍标记未完成。点击结果中的重试搜索索引清理，只重新执行公开索引对账，不停止或删除更多会话。提交响应丢失时，界面尝试核对同一计划的 Host 完成回执；无法核对的操作请刷新并检查结果，不按网络错误推断未执行。

## 删除范围

永久移除目标会话当前 JSONL 日志和全部保留格式版本，清理投影缓存、工作区关联、归档和置顶标记。缓存清理同时检查该 ID 的正常或外来版本记录、无效记录备份以及暂存删除文件，逐文件验证移除后的结果。对每个工作区调用幂等解除关联，核对持久化关联和标记，避免过滤视图遗漏。

缓存物理清理只适配已核查的 JSON per-record 后端，并绑定实际注册的后端及 domain unit。发现共享旧缓存、目标 ID 的未知缓存文件或不安全路径时，在停止和删除之前拒绝操作。匿名临时文件无法证明所属 ID，不擅自删除；其他会话缓存及共享文件保留。

可用的搜索索引通过公开搜索接口对账。搜索被配置为禁用时，先核查数据库及 WAL、SHM、journal 文件是否存在；没有索引文件则无需清理，存在旧索引则在停止和删除前拒绝操作，不擅自更改配置或删除共享数据库。

不进入回收站，无法撤销。保留工作目录文件、共享附件、外部备份、其他会话已复制或继承的文本，以及已暂停定时任务的定义。提供逻辑删除，不保证文件系统或 SQLite 空闲页、内存、外部程序日志的取证级擦除。

## 安全与兼容边界

- Agent 工具仅支持 `list` 和 `prepare_delete`。`stopActive` 仅用于展示停止影响，不授予执行权。Agent 预览不能作为浏览器删除授权。
- 最终确认仅接受经过 DSH 身份校验的浏览器所有者请求，要求专用请求头和 JSON POST。预览绑定用户、会话、持久化位置及生命周期对象，5 分钟后过期，提交一次即失效。
- 已关闭日志绑定版本和文件指纹。使用中日志另绑定精确 Session 和 Agent 对象，允许正常写入，仅在授权停止和释放后重新读取最终清单。新加载或被替换的会话要求重新确认。
- 停止前冻结所选会话的合法 Agent 创建和新回合入口。停止前后检查下级依赖，不扩大文件删除名单。
- 先释放会话原有写入所有权，再取得本批全部持久化写锁，之后才删除第一份文件。逐文件检查根目录、层级、符号链接、硬链接和文件身份，不递归删除运行时或用户目录。
- 内部兼容层只识别已核查工厂源码的 SHA-256 指纹，定位与目标 scope 元数据精确匹配的工厂复合释放 effect，遵循原有先停止并等待、再释放 scope、关闭持久化 handle、解除附着的顺序。不会直接调用裸 scope disposer、手动拔除注册项或卸载整个 Agent provider。
- 生命周期不受支持时拒绝使用中会话停止。运行时版本固定，不自动豁免版本要求。
- 最终缓存写回被跟踪并等待；已删除 ID 的迟到缓存写回受到抑制。不要在同一进程中手工复用已经删除的会话 ID，应使用新 ID 或重启后再创建。
- 目前文件删除只适配 `session-persistence-jsonl` 后端。未知文件、链接、移动的存储位置和未选中的下级会话均会阻止操作。POSIX 保留空的写锁目录以维护 inode 锁。

## 停用与卸载

通过 DSH 插件管理页面关闭会话管理插件，或移除 `@local/dsh-session-manager`。卸载不删除会话，但会等待本插件已开始的操作收尾。确认卸载后可自行移除[源码目录](<D:/杂务/dsh-session-manager>)。不要在仍链接安装时删除或移动源码。
